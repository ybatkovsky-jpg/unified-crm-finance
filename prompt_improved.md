# Шаг 3. Единый реестр переменных

Один сводный реестр на все документы (таблица Markdown + при возможности дублирующий `.xlsx`). Колонки:

1. №
2. Плейсхолдер (системное имя, см. правила ниже)
3. Группа (Клиент / Заказ / Продавец / Документ / Расчётное)
4. Описание (что подставляется)
5. Где встречается: документ → раздел/пункт/таблица/ячейка
6. Источник данных: поле карточки CRM / расчётная формула / статика (для статики — колонка 6 со значением «статика», флаг «не переменная»)
7. Физлицо: обязательно / опционально / не применяется
8. Юрлицо: обязательно / опционально / не применяется
9. Тип и формат вывода: дата (какой формат), сумма (цифрами), сумма прописью, число (десятичный разделитель), текст, паспортные данные, адрес
10. Правило/примечание; флаг «требует уточнения»

Пример строки (для наглядности, не как образец содержания):

| № | Плейсхолдер | Группа | Описание | Где встречается | Источник | Физлицо | Юрлицо | Формат | Примечание |
|---|---|---|---|---|---|---|---|---|---|
| 1 | `Doc.number` | Документ | Номер договора | Договор: шапка, п.12, Спецификация: шапка | Расчётное (нумерация) | обяз. | обяз. | текст | правило нумерации — уточнить |

**Правило:** любое поле, для которого в исходниках и описании карточки нет источника, не выдумывается, а получает флаг «требует уточнения» и попадает в список вопросов.

# Правила плейсхолдеров и условной логики

- Синтаксис — как в `docxtpl`/Jinja2: переменная `{{имя}}`, условие `{% if ... %} ... {% elif ... %} ... {% else %} ... {% endif %}`, цикл `{% for строка in строкиЗаказа %} ... {% endfor %}`.
- Нейминг — неймспейсы через точку: `Client.*`, `Order.*`, `Seller.*`, `Doc.*` (например `{{Client.fullName}}`, `{{Order.totalWords}}`). Имена переменных — латиницей, значения — на русском. Полное соответствие «плейсхолдер ⇄ строка реестра» должно быть **1:1 и в обе стороны**: в шаблонах нет плейсхолдеров без строки в реестре, в реестре нет строк без использования. Проведи такую сверку и приложи её результат.
- В статичных юридических текстах (памятка, правила эксплуатации) фигурные скобки не использовать.
- Для `.xlsx`-шаблонов укажи, как раскладывать данные: лист, диапазон строк/колонок для цикла, объединённые ячейки, форматы ячеек (число, валюта, дата), строки итогов, нумерация строк заказа.
- Для табличных частей (изделия в Бланке-заказа, товары и услуги в Спецификации, работы в Акте) опиши структуру цикла по строкам заказа и сохрани исходные колонки и форматирование таблицы.

# Правила оформления значений

- Даты — строго в формате оригинала (««___» ______ 20__ г.»), не менять стиль на «01.01.2026» там, где в оригинале прописной формат.
- Суммы — цифрами и (где требует оригинал) прописью по правилам русского языка с корректным склонением («(Сто двадцать тысяч рублей 00 копеек)»).
- Числа — десятичный разделитель и разрядность как в оригинале.
- НДС — «в т.ч. НДС …» / «без НДС» ровно так, как в оригинале; ставку НДС не додумывать, при неясности — вопрос.
- Паспортные данные — серия и номер, кем выдан, дата выдачи, код подразделения, каждое поле отдельным плейсхолдером.
- Всё — официально-деловой стиль, орфография и пунктуация оригинала сохраняются.
