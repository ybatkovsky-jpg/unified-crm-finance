# 03. Логика определения типа клиента: физлицо / юрлицо / ИП

**Цель:** гарантированно и без ручного вмешательства выбирать правильный **набор форм** и подставлять в документы верный комплект реквизитов покупателя/заказчика.

> **Решение владельца (05-Б, 05-В):** в комплекте два набора форм —
> 1) **потребительский** (существующие формы `documents/*_2026.*`, шаблоны в `02_templates/`) — только для **физических лиц**;
> 2) **B2B** (для **юрлиц и ИП**) — отдельные редакции документов без ЗоЗПП; готовятся отдельно (владелец/юрист) и добавляются вторым набором шаблонов.
> ИП оформляется как юрлицо (ОГРНИП вместо ОГРН). Единый номер договора/проекта — `ПМ2026-NNNNN` (05-В).

---

## 1. Механизм определения типа клиента в CRM

Тип определяется при создании/редактировании карточки клиента и хранится в поле **`Client.type`**:
`individual` (физлицо) | `legal` (юрлицо) | `ip` (ИП).

**Порядок определения (приоритет):**
1. **Явное поле `Client.type`** в карточке клиента — основной признак (обязательное поле).
2. **Контрольная проверка по реквизитам** (автоматическая защита от ошибок ввода; при расхождении с п. 1 — предупреждение и блокировка генерации до исправления):
   - ИНН отсутствует → физлицо;
   - ИНН = 10 цифр + КПП и/или ОГРН (13 цифр) → юрлицо;
   - ИНН = 12 цифр и/или ОГРНИП (15 цифр) → ИП.
3. Тип карточки контакта — вспомогательный признак; при противоречии приоритет у поля `Client.type`, генерация блокируется.

**Правило для генерации:** перед созданием пакета выполняется валидация реквизитов по типу (см. 03 §2). При `Client.type = individual` используется потребительский набор форм; при `legal`/`ip` — B2B-набор.

## 2. Наборы реквизитов по типам

### Физлицо (`individual`) → потребительские формы
Группы переменных реестра: № 14–24 (ФИО, пол, паспорт, адрес регистрации, телефон, e-mail). Реквизиты в потребительских формах — ФИО + паспорт + адрес + телефон. Родовые окончания («именуемый/ая», «ознакомлен(а)» и т.п.) выбираются по полу.

### Юрлицо (`legal`) и ИП (`ip`) → B2B-формы
Группы переменных реестра: № 25–39 (наименования, ИНН/КПП/ОГРН, юр. адрес, банк, подписант, основание) + № 23–24 (телефон, e-mail).

Отличия ИП от юрлица в реквизитах:
- вместо ОГРН — **ОГРНИП** (реестр № 30);
- **КПП отсутствует** — не выводится (№ 28: пусто для ИП);
- подписант — сам ИП: `signatoryName` = ФИО, `signatoryPosition` = «Индивидуальный предприниматель»;
- основание — «свидетельство о государственной регистрации / лист записи ЕГРИП».

## 3. Определение пола клиента (для потребительских форм)

По решению владельца (05-А2) пол **вычисляется по отчеству**:
- отчество оканчивается на «‑вич» → мужской (`m`);
- отчество оканчивается на «‑вна» → женский (`f`);
- иначе — по окончанию имени (‑а/-я → женский и т.п.);
- при невозможности определить — родовая форма не сокращается, печатается по умолчанию мужская форма либо форма с «(а)» (настраивается).

Парные формы в документах: «именуемый(ая)» (ДКП/ДМ/АВР/АПП), «ознакомлен(а)» (ГТ/ПАМ), «согласен(а)» (ПАМ). Для B2B-форм родовая форма не используется.

## 4. Какой набор форм — для какого документа

| Документ | ФЛ (потребительская форма) | ЮЛ/ИП (B2B-форма) |
|---|---|---|
| Договор купли-продажи | `sale_contract_2026.docx` → шаблон в 02 | B2B-редакция (разрабатывается) |
| Договор на монтаж | `assembly_service_contract_2026.docx` | B2B-редакция |
| Акт выполненных работ | `works_acceptance_act_2026.docx` | B2B-редакция |
| Акт приёма-передачи Товара | `goods_transfer_act_2026.docx` | B2B-редакция |
| Гарантийный талон | `warranty_card_2026.docx` | B2B-форма (по аналогии; при необходимости) |
| Бланк-заказа | `order_form_2026.xlsx` | B2B-редакция (лейбл «Заказчик (наименование):» и пр.) |
| Спецификация заказа | `specification_2026.xlsx` | B2B-редакция |
| Памятка покупателю | `buyer_memo_2026.docx` | потребительская (B2B не требуется) |
| Правила эксплуатации | `usage_rules_2026.docx` | B2B-форма (по аналогии; при необходимости) |

Применение B2B-форм: документы без ссылок на ЗоЗПП, реквизиты юридического лица, подписант и основание, при необходимости НДС и счёт (счёт — через 1С). Состав и тексты B2B-редакций согласовывает владелец (05-И2).

## 5. Единый номер пакета

Номер присваивается при создании проекта и одинаков для договора, бланка-заказа, спецификации и остальных документов пакета: `ПМ2026-NNNNN` (ПМ = Про Мебель, 2026 — год, NNNNN — сквозная нумерация года). Подробности и настройка серий — в 04 §2 (нумерация).
