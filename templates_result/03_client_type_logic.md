# 03. Логика определения типа клиента: физлицо / юрлицо / ИП

**Цель:** гарантированно и без ручного вмешательства подставлять в документы правильный набор реквизитов покупателя/заказчика.

---

## 1. Механизм определения типа клиента в CRM (предлагаемый)

Тип определяется в момент создания/редактирования карточки клиента и хранится в поле **`Client.type`** со значениями:

| Значение | Наименование |
|---|---|
| `individual` | Физическое лицо |
| `legal` | Юридическое лицо |
| `ip` | Индивидуальный предприниматель |

**Порядок определения (приоритет):**
1. **Явное поле `Client.type`** в карточке клиента (обязательное поле, выбирается вручную при создании карточки). Это основной признак.
2. **Контрольная проверка по реквизитам** (автоматически, как защита от ошибок ввода; при расхождении с п. 1 — предупреждение и блокировка генерации документов до исправления):
   - есть ИНН → клиент не «физлицо»;
   - ИНН = 10 цифр и заполнены КПП и/или ОГРН (13 цифр) → юрлицо;
   - ИНН = 12 цифр и/или ОГРНИП (15 цифр) → ИП;
   - ИНН отсутствует → физлицо (если тип карточки не утверждает иное).
3. **Тип карточки контакта** (если в CRM контакты разделены на «физлицо/организация») — вспомогательный признак; при противоречии с полем `Client.type` приоритет у поля `Client.type`, генерация документов блокируется до устранения противоречия.

**Правило для документов:** перед генерацией пакета выполняется валидация обязательных реквизитов по типу (списки в п. 2 ниже). Недостающие поля выводятся списком; документы не генерируются, пока не заполнены (или не подтверждён сознательный пропуск, например «ИП без КПП»).

## 2. Наборы данных по типам

### Физлицо (`individual`)
Группы переменных реестра: № 14–24 (ФИО, пол, паспорт, адрес регистрации, телефон, e-mail).
Используется в блоках: «Покупатель/Заказчик» в шапках, реквизиты в таблицах, «Ф.И.О.» в ГТ/СП/БЗ, родовая форма окончаний.

### Юрлицо (`legal`)
Группы переменных реестра: № 25–39 (наименования, ИНН/КПП/ОГРН, юр. адрес, банк, подписант, основание) + № 23 (телефон) + № 24 (e-mail).
В шапках вместо ФИО — наименование организации и блок «в лице …» с должностью, ФИО и основанием подписанта. В реквизитах — полный блок реквизитов. ИНН/КПП/ОГРН, банковские реквизиты — обязательны.

### ИП (`ip`)
Оформление — **настраиваемый режим** (переключатель в системе: «ИП оформлять как юрлицо» / «как физлицо»), по умолчанию рекомендуется «как юрлицо» с отличиями:
- вместо ОГРН — **ОГРНИП**;
- **КПП отсутствует** (не выводится);
- подписант — сам ИП: `signatoryName` = ФИО ИП, `signatoryPosition` = «Индивидуальный предприниматель»;
- основание — «свидетельство о государственной регистрации / лист записи ЕГРИП» (реквизиты).
Решение о режиме и шаблоне реквизитов ИП — вопрос владельцу (05-Г-3).

## 3. Где какой блок подставляется (сводно по документам)

| Документ | Место блока | ФЛ | ЮЛ/ИП |
|---|---|---|---|
| ДКП (`sale_contract`) | введение (покупатель), раздел 15 «Реквизиты и подписи» | ФИО + паспорт/адрес/тел. | наименование + «в лице», реквизиты, подписант |
| ДМ (`assembly_service_contract`) | введение (заказчик), раздел 8 | то же | то же |
| АВР (`works_acceptance_act`) | введение, подписи | то же | то же |
| АПП (`goods_transfer_act`) | введение, подписи/реквизиты | то же | то же |
| ГТ (`warranty_card`) | строка «Покупатель (Ф.И.О.)», подпись | ФИО | наименование (+ФИО подписанта) |
| БЗ (`order_form`) | «Заказчик (Ф.И.О.)», подпись | ФИО | наименование + подписант |
| СП (`specification`) | «Заказчик (Ф.И.О.)», подпись | ФИО | наименование + подписант |
| ПАМ (`buyer_memo`) | подпись (род окончания) | родовая форма | родовая форма не применяется (подписывает представитель — рукописно) |
| ПРАВ (`usage_rules`) | таблица реквизитов и подписей | ФИО + паспорт | юрлицо-блок |

## 4. Родовые окончания (зависят от `Client.gender`)

В оригиналах используются парные формы, выбираемые по полу покупателя:
- «именуем**ый(ая)**» — ДКП/ДМ/АВР/АПП;
- «ознакомлен**(а)**» — ГТ, ПАМ; «согласен**(а)**» — ПАМ.

Определение пола: по отчеству (‑вич/‑вна → м/ж), иначе по окончанию имени, иначе — отдельное поле «Пол» в карточке клиента (см. 05-Г-2). Для ЮЛ/ИП родовая форма не используется.

## 5. Ограничение (важно для ЮЛ)

Исходные ДКП, ДМ, АВР, АПП, ГТ юридически построены как **потребительские** (п. 1.3 ДКП — только личные нужды, ссылки на ЗоЗПП). Условные блоки выше меняют только реквизитную часть, правовые пункты остаются без изменений. **Для регулярных продаж юрлицам нужна отдельная юридическая редакция договоров** (B2B, без ЗоЗПП, с НДС и счётом) — решение за владельцем/юристом (05-Б). До её утверждения комплект для ЮЛ формируется по текущим шаблонам с юрлицо-реквизитами и пометкой о согласовании.
